# 롱폼 — 가로 아바타 영상 → 설명 영상 (+ 쇼츠 3개)

`shorts` 와 같은 도구·정책을 쓰고, **길이 때문에 달라지는 것만** 여기 적는다. 한국어, 쉬운 말, 기본은 묻지 않고 끝까지 간다.

```
① 영상 → ② 자막(대본=정답) → ③ 말 편집(순서 그대로) → ④ 장(章) 설계 → ④-1 쪽별 스토리보드 → ⑤ 렌더·장별 검수 → ⑥ 챕터·업로드 자료
```

## 하루 한 편의 묶음
- 롱폼 1개(16:9)와 쇼츠 3개(9:16)를 **각각 따로** 아바타로 생성한다. 가로 영상에서 세로를 잘라내지 않는다. 화질이 떨어지고 머리 배치가 틀어진다.
- 프로젝트 이름: `<편>-long`, `<편>-s1`, `<편>-s2`, `<편>-s3` (예: `ep01-long`).
- **쇼츠를 먼저** (`shorts` 스킬, 편당 15~20분). 그다음 롱폼. 렌더는 한 번에 하나만 돌린다. `render` 가 `public/_live` 를 비우기 때문이다.
- 채널 대본·출처는 `projects/_channel/<편>/` 에 있다. 대본이 정답 글자다.

## ⓪ 대본 구조 — 시청 시간을 붙잡는 틀 (채널 기본, 2026-10-13 사용자 결정)
대본을 쓸 때(또는 받은 대본을 검토할 때) 이 순서를 지킨다. 숫자·사실은 출처 확인된 것만 (훅이라고 과장하지 않는다).
| 구간 | 길이 | 규칙 |
|---|---|---|
| **훅** | 첫 3초 | 회사가 아니라 **시청자 자신의 돈·손해**로 시작 ("당신 앱에 남은 그 돈…"). 숫자 하나로 대비 (408억 vs 0원) |
| **스포 (열린 고리)** | ~30초 | 해결책이 **있다는 것**과 그 **조건이 하나** 있다는 것만 말하고, 답은 "마지막에 정리해 드릴게요"로 미룬다. 왜 중간을 봐야 하는지 한 줄 ("이걸 알아야 마지막이 들린다") |
| **본론 장(章)** | 장당 1.5~2.5분 | 장 제목은 하나의 흐름으로 (모으고 / 굴리고 / 남기고). **장 끝마다 다음 장 떡밥 한 줄** ("그냥 금고에 잠자고 있을까요?") |
| **훅 회수** | 본론 안 | 훅의 숫자가 나오는 곳에서 "처음에 말씀드린 그 408억" 으로 이어 준다 |
| **해결 장** | 1~1.5분 | 스포의 답을 정확히 + 시청자가 **지금 할 일** 2~3개. 이 장이 영상의 하이라이트 |
| **CTA** | 20초 | 다음 편 예고는 질문형 (다음 편 훅 미리 보기) → 구독·좋아요·하이프 |

쇼츠 3개도 같은 원리로 첫 줄은 시청자 문제·숫자, 마지막 줄은 "전체는 롱폼에서" (롱폼의 열린 고리로 보냄).

## ① 영상
`npm run new -- "<영상>" <편>-long`. 16:9 면 `video.json` layout 이 `side` 가 된다.
- 아바타는 왼쪽 520×924 카드에 얼굴 중심으로 잘려 나온다 (`src/layouts/Side.tsx`).
- 얼굴 인식이 60% 미만이면 `frames/probe_*.jpg` 를 보고 `faceX` 를 직접 적는다.

## ② 자막
`transcribe-ko` 그대로. 대본이 있으니 `script.txt` 는 대본에서 만들고(한 줄 18자 안팎), `npm run align` 일치율 90% 이상을 확인한다. 9분이면 받아쓰기에 몇 분 걸리고, 그동안 출력이 없다.

## ③ 말 편집 — 순서는 그대로
`projects/<편>-long/taste.json`:
```json
{"edit": {"structure": "as-is", "maxLength": 900, "silence": "natural", "punchIn": true},
 "broll": {"density": "medium", "exit": "wipe"}}
```
- 롱폼 대본은 처음부터 훅으로 시작하므로 재배치하지 않는다 (`edit.json` 없음).
- `npm run edit -- <편>-long`. 조각이 수백 개여도 된다 (그래프가 길면 `edit.py` 가 파일로 넘김).

## ④ 장(章) 설계 — `broll-plan` + 아래 규칙
- **장마다 `chapter` 장면을 하나** 둔다 (`{"num": "01", "title": "미리 받은 돈"}`, mode `cutaway`, 2~3초). 장면이 없는 구간의 큰 글자 위에 지금 장 이름이 뜨고(`Side.tsx` `currentChapter`), 유튜브 챕터도 여기서 나온다.
- **장마다 아바타 좌우를 번갈아**: chapter props 에 `"avatar": "right"` / `"left"`. 그 장 동안 카드가 그쪽에 있고 자료는 반대쪽에 뜬다 (`sideSwap.js`). 훅·첫 장은 왼쪽, 다음 장은 오른쪽… 처럼.
- **흐름·구조는 `FlowDiagram`** (custom): "A 가 B 로 가서 C 가 된다", 정리의 "세 갈래"처럼 돈·물건이 움직이는 말에. 반복되는 구조는 `shape: "loop"`. 장마다 한 번 정도 — 같은 영상에서 연달아 쓰지 않는다.
- 밀도는 medium, 분당 4~7개로 9분이면 장면 40~60개다. 장면이 없는 구간은 오른쪽에 지금 하는 말이 크게 뜨니 비워 둬도 된다.
- 배치: 기본 `panel` (오른쪽 무대 1190×800). 표·흐름·비교처럼 넓은 것만 `cutaway` (아바타가 왼쪽 아래로 작아짐). `above`·`below` 는 가로에선 panel 과 같아서 쓰지 않는다. `exit: avatar-grow` 는 세로 전용이다 (render 가 막음).
- 템플릿은 **장마다 섞는다.** 12종 + 커스텀 중 한 장 안에서 4종 이상. 이웃 장면 검사(`variety`)는 바로 앞 장면만 보므로, 영상 전체에서 같은 오브젝트가 3번 넘게 나오지 않게 직접 센다. 같은 틀만 반복하면 유튜브 '양산형 콘텐츠'로 보일 수 있다.
- 숫자는 **대본에서 말한 것만** (정책 `noFabrication`). 말하지 않은 연도·값은 차트에 넣지 않는다.
- 남의 로고·매장 사진은 쓰지 않는다. 오브젝트(`public/objects`)나 `motion-kit` 도형으로 그린다.
- 시각은 `npm run words -- <편>-long <글자>` 로 잡는다 (원본 시간).

## ④-1 스토리보드 — 쪽별
`npm run storyboard -- <편>-long` → 12장면씩 `out/storyboard-1.png`, `-2.png` …. **쪽마다 직접 본다.** 한 장에 다 넣지 않는다.
- 장면당 `remotion still` 을 한 번씩 돌리므로 60장면이면 몇 분 걸린다.

## ⑤ 렌더·검수
1. `npm run render -- <편>-long --check`: ❌ 0개.
2. `npm run render -- <편>-long --preview`: 절반 해상도라 빠르다.
3. `npm run look -- projects/<편>-long/out/preview.mp4 --plan projects/<편>-long/plan.json` → `preview_sheet-1.png` … 쪽마다 확인. 고치기는 최대 3번.
4. 최종 `npm run render -- <편>-long`. 이 PC에서 9분이면 20~25분 걸린다. 백그라운드로 돌리고 그동안 ⑥을 한다.
5. 최종본도 look 시트로 한 번 더 본 뒤에 알린다.

## ⑥ 챕터·업로드 자료
- `npm run chapters -- <편>-long [--intro "들어가며"]` → `chapters.txt`. 00:00 시작, 3개 이상, 각 10초 이상이 아니면 ⚠️ 가 뜬다.
- 썸네일 바탕: `npm run still -- <편>-long <원본초> --full` (1배 해상도).
- `projects/_channel/<편>/upload.md` 에 정리한다:
  - 제목, 설명란(요약 2줄 + 챕터 + 출처 링크), 고정 댓글, 태그
  - "변경되거나 합성된 콘텐츠" 표시 안내
  - 쇼츠 3개의 "관련 동영상" = 이 롱폼
- 대본에 날짜가 걸린 말("이번 달 31일")이 있으면, 올릴 수 있는 마지막 날을 맨 위에 적는다.

## 결정 요약
`shorts` 와 같은 형식으로 `projects/<편>-long/decisions.md` 에 한 번 적는다: 장 구성, 장면 수와 템플릿 분포, 고친 자막, 렌더 시간.
- **진행자 기록** 한 줄: 아바타 이름(도구 안 이름)·의상·목소리 이름. 편마다 같은 진행자가 나오는지 이 줄로 맞춘다 (`projects/_channel/host.md` 가 기준).
- **제작 시간** 한 줄: 받아쓰기·설계·미리보기·최종 렌더 각각 몇 분. 매일 운영이 되는지 이 숫자로 판단한다 (목표: 롱폼 1 + 쇼츠 3 을 사람 손 1시간 안쪽).
