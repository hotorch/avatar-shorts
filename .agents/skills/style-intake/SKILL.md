# 스타일 들이기: 레퍼런스 → 정책 · 취향 · 자산

먼저 `style/README.md` 를 읽는다 (구분 기준과 예시).

## 1. 쪼개기
레퍼런스를 **문장 단위 규칙**으로 쪼개 표를 만든다: `| 항목 | 분류 | 들어갈 곳 | 영상에 맞게 바꾼 점 |`
- 분류는 README 의 5가지 질문으로. 사용자가 "정책까지 올릴 수준"이라고 했으면 **만드는 방법**(레시피·색 규칙·금지)은 정책, **쓸지 말지·어느 것을**은 취향으로 둔다. 전부 정책으로 올리지 않는다.
- 정지 UI·인쇄용 레퍼런스의 "움직임 금지"는 영상에서 *면 안쪽*에만 적용하고, 면 전체의 등장·부유는 모션 정책(spring, 오버슈트)을 따른다고 적는다.
- 기존 정책과 부딪히면(외부 폰트, 남의 로고·핸들, 과한 글로우) 기존 정책이 이긴다. 대체안을 적는다.
- 수치로 바꿀 수 있는 말은 수치로. 단, **그 말이 지키려는 것**을 잰다 ("충분히 어둡게"의 목적은 흰 로고가 읽히는 것 → 밝기가 아니라 흰 글자 대비 ≥ 4.5). 레퍼런스 예시가 전부 통과하는지 확인한다.

## 2. 넣기
- 정책 → `style/policy.json` (`$doc` 에 출처와 바꾼 점 한 줄). 검사가 필요하면 `scripts/style.mjs` 또는 `scripts/render.mjs` 에 검사 추가.
- 취향 → `style/taste.json` 키와 기본값(팀 공용). README 의 취향 표에 한 줄. 한 사람의 값은 `style/me.json` (`reference-taste`).
- 자산 → `src/kit/` 부품 (motion-kit 규칙: 프레임 함수만, px 에 `* u`, 오프라인 폰트). 필요하면 템플릿 (`src/scenes/index.tsx`, render 의 templates 목록, broll-plan 의 templates.md).
- **레퍼런스 이미지는 반드시 직접 본다.** 텍스트 명세와 실제 이미지가 다른 경우가 있다 (예: 명세는 "진한색은 충분히 어둡게"였지만 실제로는 파랑·올리브도 있었고, 진짜 규칙은 글자 대비였다).
  - 링크가 SNS 게시물이면: 브라우저로 열어 `og:image`·`img` 주소를 뽑거나, 사용자에게 이미지 주소를 받는다.
  - 받은 주소는 `curl -sL -o <스크래치>/ref1.jpg "<주소>"` 로 받아 한 장의 시트로 이어 붙여 본다 (ffmpeg hstack/vstack).
  - 그래도 못 보면 텍스트만으로 진행하고 "이미지는 확인 못 했다"고 결과에 적는다.
- 가능하면 **숫자로 대조**한다: 같은 입력(색 등)으로 우리 부품을 렌더해 레퍼런스와 같은 위치의 색을 비교 (ΔE < 3 이면 사실상 같음). 로고·글자 자리는 빼고 잰다.

## 3. 확인
- `npm test` (정책↔코드 일치 포함), `node scripts/style.mjs <이름>` (위반 0), `npm run still -- <이름> <초>` 스틸을 **직접 보고** 레퍼런스의 체크리스트와 대조.
- 정책에 승인 목록·수치를 넣었으면 `scripts/selftest.mjs` 에 "전부 통과" 시험이 있는지 확인 (없으면 추가).
- 사용자에게는 쪼갠 표 + "정책 N개, 취향 N개, 자산 N개를 넣었어요" 한 줄.
