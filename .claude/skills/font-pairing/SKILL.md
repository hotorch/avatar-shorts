# 폰트 조합 — 하나의 정답은 없다

폰트는 맞고 틀림이 아니라 **영상마다 고르는 것**이다. 그래서 키트는 폰트 하나를 정해 두지 않고, 칸 세 개와 조합 9개를 준다.
규칙은 출발점이다. 고딕끼리도 굵기·폭이 다르면 짝이 보이고, 명조 본문도 짧은 안내에서는 버틴다. 판단은 **같은 문장을 나란히 놓고 눈으로** 한다.

## 세 칸
| 칸 | 키 | 어디에 나오나 | 고르는 법 |
|---|---|---|---|
| 강조 | `type.emph` | 큰 훅 자막, 장면 제목, 큰 숫자 | 개성은 여기서만 |
| 본문 | `type.body` | 자막, 목록, 작은 카드 라벨 | 1~2초 안에 읽혀야 한다. 담백하게 |
| 영문 | `type.latin` | 강조 글자 안의 영어·숫자 | 강조 한글과 굵기·높이가 이어지는지가 종류보다 중요 |

작은 라벨은 코드에서 늘 본문 칸이다 (`FONT.sans`). 명조가 가늘어지거나 아주 굵은 고딕이 뭉개지는 일을 칸 나누기로 막는다.

## 조합 9개
목록·쓸 수 있는지는 `npm run fonts`, 원본은 `style/policy.json` 의 `fonts.pairs`.

| 이름 | 조합 | 강조 · 본문 · 영문 | 어울리는 영상 | 조심할 것 |
|---|---|---|---|---|
| `channel` | 기본 | 학교안심 알림장 · 프리텐다드 · Instrument Serif | 무엇이든, 복잡한 화면 | 자막 글꼴은 자막 세트를 따름 |
| `clean-tech` | 클린 테크 | 에이투지체 · 프리텐다드 · Bricolage Grotesque | AI 도구, 앱 소개, IT 팁 | 고딕끼리라 대비가 작음 |
| `report` | 리서치 리포트 | 함렡 · 아스타 산스 · Newsreader | 리서치, 보고서, 비교 분석 | 복잡한 화면과 톤이 어긋날 수 있음 |
| `docu-serif` | 다큐 명조 | 본명조 · 프리텐다드 · Playfair Display | 다큐, 사회 이슈, 역사 | 어두운 영상 위 획이 약해짐 |
| `event-brush` | 이벤트 붓글씨 | 검은고딕 · 프리텐다드 · Yellowtail | 이벤트, 메뉴, 오픈 소식 | 숫자는 검은고딕으로 나옴. AI 는 A/ 로 읽힘 |
| `impact` | 오스퀘어 임팩트 | 카페24 아네모네 · 프리텐다드 · Archivo Black | 짧은 훅, 랭킹 | 오래 보면 피로함. **파일을 넣어야 씀** |
| `local-shop` | 동네 가게 | 주아 · 마루 부리 · Young Serif | 디저트, 굿즈, 동네 가게 | 긴 목록에는 무거움 |
| `study-note` | 공부 노트 | 나눔손글씨 펜 · 프리텐다드 · Caveat | 공부법, 짧은 메모 | 손글씨는 한두 낱말에만 |
| `retro` | 을지로 레트로 | 배민 을지로체 · SUIT · Abril Fatface | 노포, 맛집, 레트로 | IT 소개에는 안 맞음. **파일을 넣어야 씀** |

## /shorts 에서 묻지 않고 고르기
1. 내 취향·프로젝트 취향에 `type.pair` 가 `auto` 가 아닌 값으로 있으면 **그대로 쓴다.** 사용자가 고른 것이다.
2. `auto` 면 대본 주제로 표의 "어울리는 영상"에서 고른다. 애매하면 `channel`. `npm run fonts` 에서 ⬇️ 인 조합은 고르지 않는다.
3. `projects/<이름>/taste.json` 에 `{"type": {"pair": "..."}}` 로 적고, `decisions.md` 에 "왜 · 다른 후보 2개 · 바꾸려면" 한 줄.
4. `event-brush` 처럼 조심할 것에 걸리는 말이 대본에 있으면 다른 조합으로. `render --check` 의 폰트 ⚠️ 도 본다.
5. 렌더 전 시트에서 대표 장면을 `npm run still` 로 한 번 본다. 어두운 영상 위 명조·손글씨가 약하면 다른 조합으로 바꾼다.

같은 채널에서 시리즈로 이어지는 영상이면 내 취향에 고정해도 좋고, 주제가 바뀌면 조합도 바꿔도 좋다. 어느 쪽도 정답이 아니니 결정 요약에 다른 후보를 함께 적는다.

## 사용자가 고르고 싶어 할 때
1. 후보 2~3개를 고른다 (주제에서 하나, 대비가 큰 것 하나, 지금 쓰는 것 하나).
2. 비교 시트를 만든다. 프로젝트가 있으면 **그 영상의 말**로 나온다.
   ```bash
   npm run fonts -- sheet <이름> --pairs clean-tech,report,channel
   ```
   → `projects/<이름>/out/font-pairs.png`. 칸 하나가 폰 화면 크기다. 위는 밝은 바탕, 아래는 어두운 바탕. **시트를 직접 보고** 사용자에게 보여 준다. 볼 곳: 작은 라벨이 살아 있는지, 숫자 9·0, 영어와 한글의 높이, 띄어쓰기 간격.
3. 실제 영상에 입혀 본다: `npm run sample -- --taste '{"type":{"pair":"report"}}'` (예시 영상), 프로젝트면 `taste.json` 에 적고 `npm run still`.
4. 정한다. 이번 영상만이면 `projects/<이름>/taste.json`, 앞으로도면 `npm run me -- --set type.pair=report --why "…"`.

## 칸 섞기
조합은 시작점이다. 한 칸만 바꿔도 된다. 말로 받으면 이렇게 적는다.

| 사용자 말 | 값 |
|---|---|
| "리포트 조합인데 제목만 검은고딕으로" | `{"type": {"pair": "report", "emph": "blackhan"}}` |
| "기본에 영어만 Bricolage 로" | `{"type": {"latin": "bricolage"}}` |
| "자막만 SUIT 로" | `{"captions": {"font": "suit"}}` (조합보다 앞선다) |

- 쓸 수 있는 칸별 이름은 `npm run fonts` 맨 아래. 한글 폰트는 강조·본문, 영문 폰트는 영문 칸만 (render 가 막는다).
- 조합을 고르면 자막은 본문 칸을 따른다. 터미널 상자(`console`)는 고정폭이 모양의 일부라 그대로.
- 칸은 세 개까지. 넷째 폰트가 필요해 보이면 강조를 바꾼다.

## 내 폰트 넣기 (눈누 등에서 받은 파일)
```bash
npm run fonts -- add ~/Downloads/내폰트.ttf --label "내 폰트" --kind gothic
```
- 이 PC 에만 들어간다 (`public/fonts/local/`, git 제외). 영상에는 쓸 수 있어도 파일을 나눠 줄 수 없는 폰트가 많기 때문이다. **저장소에 올리지 않는다.**
- `add` 가 한글 글자 수, 띄어쓰기, 숫자를 재서 알린다. 글자가 작아 보이는 폰트는 크기를 맞춘다.
- `impact`·`retro` 는 `--as ohsquare`, `--as euljiro` 로 넣으면 바로 쓸 수 있다. 받는 곳은 `npm run fonts`.
- `--kind`: `gothic` 고딕 · `wide` 넓은 고딕 · `heavy` 아주 굵은 · `round` 둥근 · `serif` 명조 · `hand` 손글씨 · `script` 필기체 · `display` 장식.
- 상업적으로 쓸 영상이면 눈누 라이선스 표의 **영상** 칸을 사용자가 확인하게 안내한다. 다폰트는 "무료"여도 개인용만인 경우가 많다.

## 경험칙 (막지 않는다)
`render --check` 는 ⚠️·ℹ️ 로만 알리고, 이유가 있으면 넘어간다.
- 성격이 반대인 폰트끼리 짝을 지으면 짝이 잘 보인다 (굵은 고딕 ↔ 가는 명조, 고딕 ↔ 손글씨).
- 본문은 담백하게, 개성은 강조에서만. 게임·레트로처럼 분위기가 읽기보다 중요하면 예외.
- 손글씨·필기체는 한두 낱말. 자막 크기에서 존재감이 약해진다.
- 윤곽선·헤어라인·아주 얇은 장식체는 자막 크기에서 사라진다. 후보로 고르지 않는다.
- 숫자가 나오는 영상은 시트의 숫자를 본다 (Syne 의 9 는 g 처럼, 옛 숫자는 90 이 9o 처럼 읽힌다).

## 이 기준의 한계
어두운 세로 쇼츠 2편으로 65쌍을 비교해 고른 값이다 (판정은 AI, 실제 폰 시청·조회수는 재지 않음). 밝은 바탕과 가로 영상은 다를 수 있어서 시트와 스틸로 직접 본다. 출처: [폰트 페어링 실험](https://zexea-education.com/blog/motion-graphics-font-pairing), [font-pairing-skill](https://github.com/Sequence-st/font-pairing-skill) (MIT).
