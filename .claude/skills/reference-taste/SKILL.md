# 레퍼런스 영상 → 내 취향

사용자는 "이런 느낌"을 말로 설명하기 어렵다. 영상을 받아 **숫자로 재고 직접 본 뒤** 취향 값으로 바꾼다. 묻지 않는다 (취향 `ask`).
배운 것은 `style/me.json` 에 들어간다. **이 PC 에만** 있고 git 에 안 올라간다. 공용 기본값(`style/taste.json`)은 건드리지 않는다.
적용 순서: 정책 > plan.json > `projects/<이름>/taste.json` > **`style/me.json`** > `style/taste.json`.

## 0. 영상 받기
- 파일 경로를 받는다. 영상은 **읽기만** 한다 (복사·수정 없음).
- 링크(유튜브·인스타·스레드)만 주면 직접 받지 않는다 (로그인·저작권). "영상을 저장해서 파일로 주세요" 한 줄.
- 한 번에 여러 개면 하나씩 1~2 를 반복한다. 많을수록 정확하다 (중앙값).

## 1. 재기 (자동)
```bash
npm run reference -- <영상> [짧은-이름]
```
→ `projects/_refs/<이름>/reference.json` (숫자) · `sheet.png` (화면 전환 사이마다 한 장) → `style/me.json` 을 다시 계산하고 내 취향 카드를 보여 준다.

| 재는 것 | 취향 | 기준 (`scripts/me.mjs`) |
|---|---|---|
| 화면 전환 분당 횟수 (0.25초 사이 화면이 크게 바뀐 순간) | `broll.density` | 8 미만 low · 14 미만 medium · 이상 high (B-roll 하나 = 등장·퇴장 2번) |
| 말 사이 쉼 중앙값 | `edit.silence` | 0.22초 미만 tight · 0.4 미만 natural · 이상 off |
| 화면 밝기·색 (가운데 얼굴 자리 빼고) | `look.palette` | 어두움(0.35 미만) darktech · 밝고 따뜻함 academic · 밝고 차가움 editorial |
| 얼굴이 크게 보이는 비율 (`faceRatio`) | 참고만 | 낮으면(0.5 미만) 화면 전체 장면 위주 → 2 의 배치 판단에 쓴다 |

영상 길이는 배우지 않는다 (짧은 레퍼런스를 따라 내 말이 잘려 나간다).

## 2. 시트를 직접 보고 정하기 (숫자가 못 재는 것)
`sheet.png` 를 **직접 연다**. 분명히 보이는 것만 정하고, 애매하면 비워 둔다 (기본값이 낫다).
```bash
npm run me -- --set <키>=<값> --why "시트에서 본 것 한 줄" --by reference
```
| 본 것 | 키 | 정하는 법 |
|---|---|---|
| 자막 글자 높이 | `captions.scale` | 화면 높이 대비. 우리 1.0 = 약 3.3% (1920 중 64px). 레퍼런스 % ÷ 3.3, 0.8~1.3 으로 자른다 |
| 그림이 얼굴 위·아래 카드로 뜨는가, 분할·전체만인가 | `broll.framing` | 카드가 보이면 varied, 분할·전체만이면 split |
| 판·카드에 그라디언트가 있는가 | `look.surface` | gradient / flat |
| 컷마다 얼굴 크기가 바뀌는가 (확대) | `edit.punchIn` | true / false |
| 이웃 칸이 매번 배치·모양까지 다 다른가 | `broll.variety` | 그렇다면 strict |
| 작은 틀(사진·인물)이 계단식으로 커져 화면을 채우는가 | `broll.exit` | 그렇다면 avatar-grow (컷어웨이에서 얼굴로 돌아올 때 아바타가 커짐) |

## 2-1. 모션 레퍼런스 (짧은 모션그래픽 클립, 얼굴·말 없음)
숫자(전환 수·쉼·얼굴 비율)는 거의 의미 없다 (부드럽게 이어지는 모션은 전환 0~2번으로 잡힘). **콘택트 시트를 만들어 직접 본다**:
```bash
ffmpeg -v error -y -i <영상> -vf "fps=6,scale=240:-1,tile=6x5:padding=4:color=red" -frames:v 1 projects/_refs/<이름>/contact.png
```
(ffmpeg 빌드에 `drawtext` 가 없을 수 있다 → 시각 글자는 넣지 않는다. 칸 = 1/6초)
1. 칸을 따라 **움직임을 문장으로** 쪼갠다: 무엇이 · 어디서 · 몇 계단으로 · 어떤 리듬으로 (예: "가운데 작은 틀 → 3계단으로 커져 화면을 채움").
2. 사용자가 "이 부분이 좋다"고 하면 **그 움직임만** 가져온다. 나머지(타이포·라벨·색)는 가져오지 않고 결정 요약에 "안 가져온 것"으로 적는다.
3. 이미 있는 것에 맞춘다: 취향 키(`broll.exit=avatar-grow` 등) → `npm run me -- --set … --by reference` / 없으면 `motion-kit` 으로 일반 이름의 커스텀 장면(`StackCarousel` 처럼) / 반복해서 쓸 전환이면 레이아웃 + 정책(만드는 법)·취향(쓸지) 키를 새로 (`style-intake`).
4. 그림 자리에는 레퍼런스 사진 대신 **이 영상의 아바타**나 3D 오브젝트를 쓴다. 색은 트라이어드에서만 (정책 `sceneColors`).
선례: avatar-v03 (`projects/avatar-v03/decisions.md`, `style/README.md` 의 예).

## 3. 가져오지 않는 것 (정책이 이긴다)
- 그림·글자·로고·브랜드·핸들·같은 문구. **구도와 리듬만** 배운다.
- 승인 3색 밖의 색 (팔레트 분위기만 가져온다), 외부 폰트, 파티클·과한 글로우, 배경음악 (원본 음성이 주인공).
- 레퍼런스가 정책과 부딪히면 카드 아래에 "안 가져온 것: …" 한 줄로 알린다.

## 4. 알리기
`npm run me` 카드를 그대로 보여 주고 한 줄 더:
- "이 PC 에만 저장했어요. 다음 영상부터 이 취향으로 만들어요."
- 레퍼런스가 2개 미만이면 카드의 💡 줄 (좋아하는 쇼츠 하나 더).

## 5. 고치기
| 사용자 말 | 할 일 |
|---|---|
| "그건 내 취향 아니야" (특정 값) | `npm run me -- --set <키>=<값> --why "사용자가 고침"` (by user 가 레퍼런스보다 이김) 또는 `--unset <키>` |
| "그 레퍼런스는 빼줘" | `npm run me -- --remove <이름>` (나머지로 다시 계산) |
| "내 취향 보여줘" | `npm run me` |
| "내 취향 초기화" | `style/me.json` 을 지운다 (사용자 파일이 아니라 우리가 만든 파일. 지우기 전에 카드를 한 번 보여 준다) |

`shorts` 결과를 보고 같은 방향으로 두 번 고치면(예: "자막 더 크게") 그것도 여기에 기억한다: `npm run me -- --set captions.scale=1.2 --why "자막 더 크게 (두 번)"`.
