# 말 편집: 무음 제거 + 바이럴 구조

원칙: **말을 바꾸지 않고 순서와 길이만 바꾼다.** 새 문장·요약·윤문 금지(정책 `captionsVerbatim`). 자르거나 옮길 수만 있다.

## 1. 자막 번호 보기
```bash
npm run edit -- <이름> --list
```

## 2. 구조 정하기 → `projects/<이름>/edit.json`
취향 `edit.structure` 가 `as-is` 면 edit.json 을 만들지 않는다(무음만 줄인다). `hook-first` 면 아래 순서로 판단한다.

**훅 고르기** — 아래 점수가 가장 높은 문장(1~2개 자막, 3초 이하)
| +2 | 결과·반전·부정 ("한 번도 안 켰습니다", "3일 만에", "틀렸습니다") |
| +2 | 혼자 떼어 놔도 뜻이 통한다 (앞 문장 없이 이해됨. "이걸", "그래서" 로 시작하면 −2) |
| +1 | 호기심 틈 (답은 뒤에 나옴), 질문 |
| +1 | 실제로 말한 숫자 |
| −3 | 인사, 자기소개, "오늘은 ~를 알려드릴게요" |

훅 점수가 3 미만이면 옮기지 않는다 (억지 훅은 더 나쁘다). 원래 첫 문장이 이미 훅이면 그대로.

**나머지**
- 훅을 뺀 자리의 앞뒤가 자연스럽게 이어지는지 읽어 본다. 끊기면 훅을 반복(`order` 에 두 번)하지 말고 다른 후보를 고른다.
- 인사·예고("오늘은…")·같은 말 반복은 뺀다.
- CTA(구독, 링크, "쓰시면 됩니다")는 맨 끝. CTA 뒤 꼬리말은 뺀다.
- `edit.maxLength` 를 넘으면 예시·부연부터 뺀다. 주장·숫자·결론은 남긴다.

```json
{"order": [[15, 16], [1, 14], [17, 23]],
 "why": "훅: '편집 프로그램은 한 번도 안 켰습니다'(결과+부정, 혼자 통함)를 맨 앞으로"}
```
번호는 1부터, 양 끝 포함. 목록에 없는 번호는 잘린다.

**손으로 자르기** `"cut": [[시작, 끝], …]` (원본 초): 인식되지 않은 "음", 말실수, 기침, 되풀이한 말. 사용자가 "그 부분 잘라줘"라고 하면 여기에.
안에 든 단어는 자막에서도 빠진다. 시각은 `npm run words -- <이름>` 로 찾는다. 문장 중간을 자를 땐 단어 경계에 맞춘다.

## 3. 실행
```bash
npm run edit -- <이름>
```
- 무음은 취향 `edit.silence`(tight 0.16s / natural 0.30s / off), 정책 `edit.maxSilenceKept`(0.45s)를 넘게 남기지 않는다.
- 덩어리 경계는 문장 사이 무음 한가운데 → 말이 잘리지 않는다. 경계마다 8ms 페이드.
- 결과: `edit.mp4`, `words.edit.json`, `captions.edit.json`, `cuts.json` (펀치인 줌 시각 포함). 새 순서의 자막이 출력된다 → **소리 내어 읽듯 한 번 읽어 보고** 어색하면 order 를 고쳐 다시.
- `render` 는 편집본을 자동으로 쓴다. **plan.json 은 계속 원본 시간(words.json)으로 쓴다** — render 가 편집본 시간으로 옮긴다. 그래서 edit.json 을 바꿔도 plan 을 다시 쓸 필요가 없다.
  (단, 장면 하나가 재배치 경계를 넘으면 ❌ → 장면을 나눈다. 편집으로 1.2초보다 짧아진 장면도 ❌ → 늘린다.)

## 4. 알리기
결정 요약에 한 줄: "무음 1.2초를 줄이고, '편집 프로그램은 한 번도 안 켰습니다'를 첫 문장으로 옮겼어요 (27.0→25.8초)".
